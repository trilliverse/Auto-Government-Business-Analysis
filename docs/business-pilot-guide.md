# 业务试用操作手册

## 适用范围

当前版本适合由项目管理员陪同业务人员试用。Stage 1 已完整验收；Stage 2/3 已具备证据、审核和冻结机制，但业务人员仍需确认处室权限、异常路径和最终成果。

## 1. 新建案件

在 Harness 新建会话，选择“政务流程梳理”，指定一个空工作目录，然后说：

> 新建一个职责和数字化流程梳理案件。请先读取职责材料，只生成 Gate 0 审核稿，不要直接进入下一阶段。

业务人员提供：

- 单位、处室；
- 职责文件；
- 来源是否为正式现行三定；
- 纳入/排除范围；
- 特殊口径。

不需要上传通用工作指引。

## 2. Gate 0：确认输入

检查：职责是否完整、来源是否可信、范围是否正确。明确回复批准、退回或修改。没有明确批准，Agent 不得进入 Stage 1。

## 3. Gate 1：确认事项

逐项检查拆分和四类职能。允许修改、拆分、合并、改类和排除。批准后生成不可变 JSON 和四列 Excel。

## 4. Stage 2：上传系统资料

将系统设计、需求、操作手册、制度和实际材料放在受控目录。Agent 先建立索引和证据候选，不应直接写最终流程。人工先筛掉范围错配和背景材料。

## 5. Gate 2：确认数字化与流程

重点确认：

- “有/无/待确认”是否合理；
- “无”是否有明确人工意见或正面材料；
- 不同业务范围没有被混用；
- 目标处室没有被扩大为主责或审批主体；
- direct evidence 有文件哈希、定位和短引文；
- 仍不清楚的问题保留在待确认清单。

批准后生成九列 Excel，G 列泳道图仍为空。

## 6. Gate 3：先审逻辑，再审图

先审核泳道主体、节点、判断、退回和最终成果，再渲染 Draw.io。系统不能作为泳道。Draw.io 需要人工调整布局并再次确认。

## 7. 查看状态和审计

```powershell
python pipeline/src/case_status.py workcases/<case-id>
python pipeline/src/audit_case.py workcases/<case-id>
```

审计通过仅说明版本链和文件一致，不代表业务未决问题已解决。

## 8. 试用反馈建议

记录：

- 每个 Gate 的人工耗时；
- 模型一次通过率；
- 最常见的拆分和分类错误；
- 证据候选有效率；
- 需要业务人员补充的材料类型；
- 泳道图平均修改量；
- 哪些命令或文件对业务人员过于复杂。

这些反馈决定是否开发专门 Web 审核界面。
